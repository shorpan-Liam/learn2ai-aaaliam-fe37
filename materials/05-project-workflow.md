# 05 React 项目与学习路线

## 学习目标

- 了解现代 React 项目的基本组成。
- 能组织组件、样式、数据与测试文件。
- 掌握基础调试和质量检查方法。
- 获得从入门到项目实践的学习路线。

## 1. 创建项目时的选择

学习阶段可使用支持 React 的现代构建工具快速创建单页应用。正式项目应根据需求选择合适的 React 框架或构建方案。

选择时需要考虑：

- 是否需要服务端渲染或静态生成。
- 是否需要路由、数据加载和后端能力。
- 部署平台和团队已有技术栈。
- 项目规模、SEO、性能与维护周期。

不要把“如何创建项目”误认为 React 的核心。组件、状态和数据流才是更可迁移的知识。

## 2. 一个简单的目录结构

```text
src/
├── app/
│   └── App.jsx
├── components/
│   ├── TaskForm.jsx
│   └── TaskList.jsx
├── features/
│   └── tasks/
│       ├── TaskItem.jsx
│       └── task-utils.js
├── styles/
│   └── global.css
├── main.jsx
└── test/
    └── setup.js
```

目录结构应随项目增长逐步演化。小项目不需要提前建立大量空目录。

## 3. 组件设计检查表

1. 组件的单一职责是什么？
2. 数据由谁拥有？
3. 哪些是 Props，哪些是 State？
4. 是否存在可以直接计算的派生值？
5. 用户事件发生后，状态在哪里更新？
6. 加载、错误、空数据和成功状态是否都被处理？
7. 组件是否具备可访问的名称、标签和键盘操作？

## 4. 调试方法

遇到界面错误时，先检查：

- 当前 Props 和 State 是什么。
- 事件处理函数是否执行。
- 状态更新后组件是否重新渲染。
- 条件渲染是否走到预期分支。
- 网络请求的状态码和返回内容是否正确。

React 开发工具可用于查看组件树、Props、State 和渲染行为。浏览器控制台和网络面板则适合排查运行错误与请求问题。

阅读错误信息时，记录错误类型、完整消息、首个指向自己代码的行号、触发步骤和输入数据。

## 5. 代码质量

一个基础 React 项目通常应包含：

- 格式化工具，统一代码风格。
- 静态检查工具，发现常见错误与 Hook 依赖问题。
- 自动化测试，保护关键交互。
- 清晰的提交记录和项目说明。

测试应从用户可观察行为出发，而不是依赖组件内部实现细节。例如，测试点击“添加”后新任务是否出现在列表中。

## 6. 性能观念

先保证行为正确，再根据测量结果优化。不要默认给所有值添加缓存。

- State 放在真正需要它的层级。
- 避免在 Effect 中进行不必要的状态同步。
- 列表使用稳定的 `key`。
- 大型功能按页面或路由拆分代码。
- 对昂贵计算或频繁渲染使用性能分析工具验证。

## 7. 可访问性基础

- 优先使用 `button`、`label`、`nav` 等语义化元素。
- 图片提供有意义的 `alt`，装饰图片使用空 `alt`。
- 表单输入与标签建立关联。
- 不要只依赖颜色传递状态。
- 保证键盘可以完成核心操作。
- 异步变化应有清晰的加载与错误提示。

React 不会自动让页面具备可访问性，组件设计仍需遵循 Web 标准。

## 8. 推荐学习路线

第一阶段：巩固 HTML 语义、CSS 布局，以及 JavaScript 数组、对象、模块、异步与 DOM 基础。

第二阶段：掌握 JSX、组件、Props、State、事件、列表、表单、状态提升、Effect 和请求状态。

第三阶段：学习路由、TypeScript、测试、可访问性、服务端状态管理、React 框架、部署和性能分析。

## 综合实践：学习任务清单

### 基础要求

- 新增、完成和删除任务。
- 按“全部、进行中、已完成”筛选。
- 显示剩余任务数。
- 提供输入校验和空状态。

### 进阶要求

- 使用本地存储保存任务。
- 支持编辑任务标题。
- 增加加载、错误和确认反馈。
- 为核心交互编写测试。
- 检查键盘操作和表单标签。

### 复盘问题

1. 哪个组件拥有任务数组，为什么？
2. 筛选后的数组是否需要单独存入 State？
3. 哪些逻辑适合提取为自定义 Hook？
4. 如果任务来自服务端，需要新增哪些状态？
5. 如何判断一次性能优化是否真的有效？
